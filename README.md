# Doorway_Detection-Robot

Wall-following robot with **sensor fusion** (Naive Bayes) and **PID** control.  
You learn **CPTs** from measurements, then fuse live/batched readings to estimate:

- probability you **just passed a door** (and a temporal “~10 cm ago” helper)
- **distance from wall** as a probability distribution → expected distance for PID

The repo also includes a small demo that produces plots and a CSV you can open in Excel.

## 2) Learn CPTs from your data

The learner reads a CSV with columns like:

- `location` (discrete labels you trained on: e.g., `wall_close`, `wall_mid`, `wall_far`, `door_start`, `door_passed`)
- discrete sensor features that match your runtime feature keys (e.g., `IR1..IR9`, `PIDP*`, `PIDD*`, `PIDI*`, `BI*`)

Use the provided sample, or point to your own CSV:

```bash
# using the sample dataset in /data
python -m src.belief_network_learn --data data/measurements_v2.csv --out cpts --smoothing 1.0

# After this, cpts/ will contain many files named cpt_<feature>.csv
ls cpts | head
```

## 3) Run the demo (plots + CSV)

The demo slices part of the dataset, runs the Bayesian Network, and saves:

- `posterior_rep.png` (representative posterior)
- `timeseries.png` (expected distance & door probabilities)
- `belief_timeseries.csv` (Excel-friendly)

```bash
# Default: reads data/measurements_v2.csv, uses cpts/, writes to docs/images/
python -m src.demo

# Custom output folder
python -m src.demo --outdir runs/exp1

# Explicit data and CPT directories
python -m src.demo --data data/measurements_v2.csv --cpts cpts --outdir runs/exp2
```

## 4) API

```bash
from src.belief_network import belief, door_passed_10cm_ago

# 1) instantaneous fusion
bmap = belief(
    sonar_readings={"IR1": 7, "IR5": 5},  # keys & bins must match what you trained
    inner_configuration={"cpts_dir": "cpts", "door_states": ["door_passed"]}
)
# bmap = {"locations":[...], "p_location":[...], "p_door_passed": float}

# 2) temporal helper: “door ~10 cm ago”
p_ago = door_passed_10cm_ago([bmap, ...], cm_per_step=1.0)
```
### Expected distance for control

```bash
loc_to_cm = {"wall_close":5.0, "wall_mid":6.5, "wall_far":9.0,
             "door_start":7.5, "door_passed":9.5}
expected_cm = sum(p * loc_to_cm.get(l, 7.0) for l,p in zip(bmap["locations"], bmap["p_location"]))
```

### PID control

```bash
from src.pid import PID
pid = PID(kp=0.4, ki=0.02, kd=0.1, setpoint=6.0)
u = pid.update(measurement=expected_cm, dt=0.1)
```

## 5) Using your own measurements

1. Put your CSV under `data/` (or anywhere).  
2. Run the learner:

   ```bash
   python -m src.belief_network_learn --data data/my_robot_logs.csv --out cpts --smoothing 1.0
   ```
3. Ensure your runtime feature keys (e.g., ```reading = {"IR5": bin(value)}```) exactly match the column names in your CSV.

## 6) Common Issues
- ```FileNotFoundError: cpt_IR1.csv```  
  You didn’t generate CPTs yet. Run the learner (Step 2).
- ```ModuleNotFoundError```  
  Run with module syntax from repo root:
  ```bash
  python -m src.demo
  ```
- `Pylance says “pandas cannot be resolved"`  
  Ensure VS Code is using your ```.venv``` interpreter.
- Empty/odd plots  
  Adjust ```start, end``` in ```src/demo.py``` or run with flags.

## 7) ROS 2 integration
#### 0) Prerequisites
- ROS 2 (e.g., Humble on Ubuntu 22.04)
- Colcon build tools  
  ```bash
  sudo apt update
  sudo apt install -y python3-colcon-common-extensions
  sudo apt install -y python3-pandas python3-numpy
  ```
#### 1) Learn CPTs at least once (creates ./cpts/*)  
```bash
python -m src.belief_network_learn --data data/measurements_v2.csv --out cpts --smoothing 1.0
```
#### 2) Build the ROS2 Package
```bash
cd ros2_ws
colcon build
. install/setup.bash
```
#### 3) Launch the node
```bash
ros2 launch wall_follow wall_follow.launch.py
```
If it starts correctly, you will see:  
```bash
[wall_follow_node-1] [INFO] ... WallFollowNode started with Bayesian + PID
```
#### 4) Topics (defaults)
The node expects simple “preprocessed” topics (you can adapt to your robot’s topics easily):
##### Subscriptions
- `/ir/side_cm` — `std_msgs/Float32` (side distance in cm)  
- `/ir/front_cm` — `std_msgs/Float32` (front distance in cm, optional)  
- `/bumper/hit` — `std_msgs/Bool` (bumper) 
##### Publications
- `/cmd_vel` — `geometry_msgs/Twist`  

- If your robot publishes different message types (e.g., `sensor_msgs/Range` or iRobot Create 3 custom messages),  
edit the callbacks in **`wall_follow_node.py`** to read the appropriate fields and convert to cm before binning.

#### 5) Parameters (tunable at launch)

Set in `launch/wall_follow.launch.py` or via `ros2 param set`:

| Name        | Type     | Default          | Meaning                                    |
|-------------|----------|------------------|--------------------------------------------|
| `cpts_dir`  | string   | `cpts`           | Path to learned CPT CSVs                   |
| `door_states` | string[] | `['door_passed']` | Which door states to consider              |
| `setpoint_cm` | float  | `6.0`            | Desired wall distance (cm)                 |
| `kp, ki, kd` | float   | `0.4 / 0.02 / 0.1` | PID gains                                 |
| `base_linear` | float  | `0.05`           | Forward speed (m/s)                        |
| `angular_scale` | float | `1.0`           | Scales PID output → angular z (rad/s)      |



##### Check at runtime

```bash
ros2 param list /wall_follow_node
ros2 param get /wall_follow_node cpts_dir
```
